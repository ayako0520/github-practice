GITHUB-PRACTICE ROUTE MAP - 全26駅

ブランチ→変更→PR→マージ
ボタン1つ、文字1つ単位で追う路線図

「なんとなく分かった気がする」を卒業するための資料です。5本の路線（ブランチを作る／変更する／コミットする／PRを出す／マージする）を、駅（1アクション）ごとに止まりながら進みます。 実際にこの通りに操作して生まれたのが マージ済みのお手本PR #1 です。並べて見ながら読むと迷いません。

1 ブランチを作る 2 変更する 3 コミットする 4 PRを出す 5 マージする
PART 1 / 5

ブランチを作る

1

リポジトリのトップページを開く

github.com/ayako0520/github-practice を開きます。ここが今回の「駅」の出発点です。

github.com/ayako0520/github-practice
main ▾ Code ▾ Fork
README.md - CONTRIBUTING.md - docs/ - examples/ - .github/
2

「main」と書かれたブランチボタンを見つける

画面左上の main ▾ というボタンが、今どのブランチを見ているかの表示です。今はここが main になっています。

main ▾← ここ
3

ブランチボタンを1回クリックする

クリックすると、ブランチを検索・作成できる小さなパネルが開きます。

Find or create a branch...
main
4

検索欄に、新しいブランチ名を1文字ずつ打つ

検索欄をクリックしてカーソルを置き、docs/add-term と実際にキーボードで1文字ずつ入力します。d, o, c, s, /, a, d, d, -, t, e, r, m の順です。

docs/add-term
5

「Create branch: docs/add-term from main」をクリック

入力すると自動で候補が出てきます。緑色でハイライトされた行をクリックすると、その場で新しいブランチが作られます。

docs/add-term
+ Create branch: docs/add-term from main
6

ブランチ表示が切り替わったことを確認

左上のボタンが docs/add-term ▾ に変わっていれば成功です。今この瞬間、あなたは main とは別の「支線」の上にいます。main は一切触れていないので安心してください。

docs/add-term ▾
乗り換え：ここから「変更する」ライン（緑）
PART 2 / 5

ファイルを変更する

7

docs フォルダ → glossary.md の順に開く

ファイル一覧から docs をクリックし、次に glossary.md をクリックしてファイルの中身を表示します。

github-practice / docs / glossary.md
8

右上の鉛筆アイコン（Edit this file）をクリック

ファイル表示画面の右上あたりに、鉛筆の形をしたアイコンがあります。これが編集モードへの入り口です。

Raw Edit
9

直したい行にカーソルを置く

表の一番下の行あたりをクリックして、キーボードで打つ場所（カーソル）をそこに固定します。狙いを外すと関係ない場所を壊してしまうので、ここは焦らず。

08 | フォーク | 他人のリポジトリを自分のアカウントにコピーすること |
09 | ▌ |
10 | Issue | バグ報告や質問を書いておくチケット |
10

1文字ずつ打って新しい行を書く

キーボードで実際に打ちます。ここが「変更」そのものです。1文字打つたびに画面にその文字が現れます。

09 | レビュー | 他の人のPRを読んでコメント |
11

打ち終えた内容を見直す

スクロールして全体を眺め、誤字や打ち間違いがないか確認します。他の人の行を消していないかも必ずチェック。

+ | レビュー | 他の人のPRを読んでコメントすること |
乗り換え：ここから「コミットする」ライン（オレンジ）
PART 3 / 5

コミットする

12

画面を下までスクロールする

編集画面の一番下に「Commit changes」という入力欄のかたまりがあります。そこまでマウスホイールでスクロールします。

scroll down
13

1行目の入力欄に、変更内容を1文字ずつ打つ

これが「コミットメッセージ」、この変更に付ける短い名札です。「用語集にレビューを追加」のように、何をしたか分かる言葉にします。

用語集にレビューを追加
14

2行目の大きな欄に、補足説明を書く（任意）SKIP OK

なぜその変更をしたか、詳しく書きたい時だけ使います。空でも次に進めます。

用語集の「レビュー」の説明が抜けていたため追加しました。
15

「Commit directly to the docs/add-term branch」を確認

ラジオボタンがこちらに丸印されているか見ます。これで main には触れず、自分のブランチだけに保存されます。

Commit directly to the "docs/add-term" branch.
16

緑色の「Commit changes」ボタンをクリック

これで変更が正式に記録されます。押した瞬間、あなたの支線（ブランチ）に新しい駅ができるイメージです。

Commit changes
乗り換え：ここから「PRを出す」ライン（紫）
PART 4 / 5

プルリクエストを出す

17

黄色いバナーを探す

コミット後、リポジトリ画面の上のほうに「docs/add-term had recent pushes」という黄色い帯が出ます。見つけたら次へ。

docs/add-term had recent pushes 1 minute ago Compare & pull request
18

「Compare & pull request」ボタンをクリック

押すと、変更内容を確認しながらPRを作る画面に移動します。

.../compare/main...docs/add-term
19

「base: main」と「compare: docs/add-term」を確認

「main に、docs/add-term の変更を取り込みます」という向きが合っているかチェックします。ここが逆だと事故のもとです。

base:main ↔ compare:docs/add-term
20

タイトルと説明を1文字ずつ入力する

タイトル欄・説明欄それぞれをクリックし、何をしたPRかを書きます。あとで見た人が分かる言葉を選びます。

事例: 用語集にレビューを追加
用語集に「レビュー」の項目を追加しました。空欄になっていた説明を埋めています。
21

緑色の「Create pull request」ボタンをクリック

これで正式にPRが作成されます。ここまでで main は一切変更されておらず、あくまで「お願い」を出しただけの状態です。

Create pull request
乗り換え：ここから「マージする」ライン（赤）
PART 5 / 5

マージする

22

「Files changed」タブで差分を確認

タブを切り替えると、追加した行が緑、消した行が赤で色分け表示されます。これが「実際に何が変わるか」の最終確認です。

ConversationCommitsFiles changed
+ | レビュー | 他の人のPRを読んでコメントすること |
23

緑色の「Merge pull request」ボタンをクリック

内容に問題がなければ押します。自分のPRを自分でマージする練習もこのリポジトリではOKです。

Merge pull request ▾
24

続けて出てくる「Confirm merge」を押す

確認のダイアログが出るので、もう一度クリックして最終確定します。2段階になっているのは、うっかりマージ防止のためです。

Confirm merge
25

「successfully merged」の表示を確認

紫色の帯で完了メッセージが出れば、あなたの変更は無事 main に取り込まれました。おめでとうございます。

Pull request successfully merged and closed
26

「Delete branch」で片付ける任意

使い終えた docs/add-term ブランチはもう不要なので、グレーのボタンで削除できます。消しても main の内容には影響しません。

Delete branch

到着です、おつかれさまでした

ここまでの26駅が、そのまま実際にこのリポジトリで再現できます。間違えても壊れても大丈夫な練習場です。 まずは docs/glossary.md か docs/self-introduction.md あたりから、自分のペースで1周してみてください。
